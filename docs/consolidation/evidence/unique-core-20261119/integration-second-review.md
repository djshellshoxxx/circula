## Compatibility checks

**Listing API bytes.** `ListingRevision` retains the former ETag's field order, NUL separators, UTC millisecond timestamp format, exact decimal price string and first 12 SHA-256 bytes. The API adds the same quote characters as before. I compared this directly with the former `ts`, `minor` and `etagOf` implementations; the added fixed-value tests also cover an unpriced listing and a price beyond JavaScript's exact-integer range.

**Historical audit anchors.** The optional `Platform` field is omitted from version 1 canonical JSON. Its placement therefore leaves historical field order and MAC input unchanged. Version 1 verification keeps network-only coverage explicit. Version 2 requires a platform checkpoint, validates unique network scopes and sequence/hash combinations, and allows an explicit zero checkpoint to cover no past events. An entirely empty version 2 anchor has no database identity yet and can remain valid after ordinary first writes. Nonempty version 2 checkpoints require identity. Existing historical checkpoints are compared against their recorded sequence, so later legitimate growth is allowed.

**Historical backup signatures.** `LedgerSummary.PlatformAudit` is optional and omitted when decoding older manifests. The previous canonical version 2 manifest bytes are therefore retained; the new field participates in current signatures when present. The legacy HMAC calculation branch is unchanged. The new test source constructs the historical canonical payload independently, checks its signature, and verifies that adding/changing coverage changes the authenticated payload.

**Closure migration and API.** Migration 22 adds one nonnegative version column with default 0. It does not rewrite historical timestamps, hashes, balances, entries or audit records. Existing hashes remain version 0 and receive an explicit unsupported-recomputation response because their original generation timestamp was not saved; they are neither silently replaced nor reported as a mismatch. A closed record with no hash remains eligible for a version 1 retry. The DTO and OpenAPI both expose checkpoint version metadata. New test source covers migration from version 21, database/service reopening, elapsed time, changed covered metadata, cancellation/retry, legacy and unknown versions, and administrator-only API behavior.

## Cross-feature checks and limits

The platform audit filter is an exact `network_id = ''` match, rather than an all-network query. Platform verification introduces no audit or consistency-run write. Closed-network checkpoint exports still use ordinary export authorization, quota/audit handling and a rechecked export snapshot. Exported ledger table and column order are unchanged. The persisted closure timestamp is reread after completion, so millisecond storage precision is used consistently after restart.

I did not find a source-level uncertainty requiring a separate diagnostic fixture or duplicate compilation in this pass. Test cases described above were inspected, not executed by this reviewer. The no-finding result applies to the named committed diff and does not assert exhaustive feature acceptance or qualify later changes.
