# Future module remaining work — 2026-11-20

## Scope and estimation assumptions

This inventory credits the implementation present in the exact source commits below, including recovered work and repairs. It does not authorize Core integration, activation, deployment or a release. All 15 inspected `feature.json` files declare `enabled: false`, `integration: HOLD`, and an empty `depends_on_future_features` list. Their exact Git blob identities are recorded below.

The ranges are planning estimates by the consolidation worker, not measured completion percentages or delivery commitments. They assume one experienced Go engineer familiar with Circula, an individually approved feature, and resolution of the relevant product and operating-policy decisions. They cover the identified implementation, adapter tests and documentation work. They exclude waiting for decisions, outside reviews, CI queues, devices, external peers or providers, production acceptance and unresolved optional scope. Shared adapter work and future Core changes overlap, so adding these ranges would not produce a reliable delivery forecast.

Every eventual integration requires qualification against the then-current Core: tenant and authority boundaries, session/CSRF behavior where applicable, migration and restore behavior, ledger invariants, and relevant native and browser workflows. An isolated module test pass does not qualify an absent Core adapter. Current provider checks and branch merge qualification remain separately recorded in the consolidation receipts.

### Messaging performance qualification

At reviewed source `ef4a11975ab9159f44bcb8fa10fa6d2a1d585c45`, [VALIDATION.md][messaging-validation] records a historical diagnostic benchmark with 10,000 synthetic messages of 3,900 bytes, one Go scheduler thread and three iterations per query. It reports 633,055 ns/op for an early hit and 87,842,174 ns/op for a miss, with the expected result counts. These are retained historical measurements, not a rerun for this report or a production latency objective.

That same record explicitly says heavy-client contention, larger retained-history workloads and cancellation during an active scan were not measured. [HANDOFF-MILESTONE-F.md][messaging-handoff] identifies the source-level limitation: a missing-substring search scans the remaining conversation while holding the existing SQLite writer reservation; a result cap does not cap query work. It requests realistic workload and cancellation qualification without assuming that a private-message index should be added.

Accordingly, this report records an open qualification gap and contingent remediation. It does not claim that a production contention failure has been demonstrated, that a service objective was missed, or that a particular optimization is already required. The estimate does not include an undefined indexing or storage redesign.
