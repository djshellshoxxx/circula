# Account active-session flow

## Accepted scope

The account-and-security screen inventory in `docs/specs/08-ux-accessibility.md` requires a session list with revoke actions. `docs/dev/MESSAGES.md` explicitly recorded that no page existed. The existing session repository already stores owner, creation, last activity, expiry and revocation state. This work completes that flow without device/IP collection, a timeout change or a new recovery policy. The API-036 repair adds migration 0020 for random public selectors and indexed bounded reads.

## Behavior and boundaries

- `ListOwnSessions` requires a live session and scopes every query to its person. It returns one bounded page; dead sessions are omitted using the same idle, absolute and current-role lifetimes as authentication.
- A random persisted public selector is returned for revocation. Neither bearer values nor stored credential hashes are returned in HTML, API responses or cursors. Selectors are not credentials and do not authorize access without a live owner session.
- `RevokeOwnSession` rechecks the caller's live session inside the write transaction, checks target ownership again in SQL and records the audit atomically. Unknown and foreign selectors are indistinguishable. The audit identifies the person and whether this was the current session; it contains no session identifier (DAT-031).
- `/account/sessions` is linked from account security and shows up to 25 active rows per page. The no-JS Next page link appears whenever the bounded service returns a continuation, including an empty filtered page. A read-only confirmation page uses direct indexed owner lookup to identify the sign-in and describe the consequence, including targets beyond the first page. The confirmed POST needs CSRF. Ending the current sign-in clears the browser session and rotates CSRF before returning to sign-in.
- `GET /api/v1/me/sessions` and `DELETE /api/v1/me/sessions/{session}` are cookie-only owner operations. The API uses the existing signed cursor format, binds it to the person, route and persisted-selector ordering version, caps response pages at 100 and continues correctly when the boundary session is revoked. The adapter seals the service continuation without performing a second scan or dropping an empty page's cursor.
- Password-change requirements retain their existing semantics: the HTML authentication gate redirects first; API reads remain available, while revocation refuses until the required password change. Other sessions and API tokens are not revoked by a single-session action.

## Verification

New repository contract, service, API, HTML and catalogue regressions cover ownership, credential secrecy, stale caller rejection, exact expiry boundaries and role limits, transactional audit rollback, current-browser sign-out, CSRF, explicit confirmation and paginated continuation after a boundary revocation. The machine-readable OpenAPI contract and route authorization inventory include both API operations and all HTML routes. The contract harness exercises the documented list and revoke operations.

Before the bounded-listing repair, local production builds of `internal/service`, `internal/api`, `internal/web` and the driver-neutral `internal/storetest` passed with Go 1.26.11. The catalogue race suite passed (1.055 seconds). The actual embedded session templates and catalogue also passed their original four rendering states under race instrumentation with all production web files (1.292 seconds), without a database substitute. Catalogue JSON, OpenAPI YAML and the changed browser JavaScript parsed successfully. Both new templates are registered in the shared browser axe/target-size inventory and Go page-structure suite. These historical results do not qualify the subsequent pagination repair.

The initial independent source review approved ownership, live-caller authorization, cookie/CSRF enforcement, role/expiry boundaries, atomic audit, selector secrecy, repeat semantics and boundary-revocation pagination. The reviewer identified the missing browser template inventory entries and requested explicit audit-payload secrecy coverage; both are included. The full SQLite behavioral, browser and contract suites still require CI qualification because local `modernc.org/libc` compilation exceeded the environment memory limit. No runtime pass is claimed for those suites until their CI result is recorded.

## Bounded-listing repair and migration

The initial owner-scoped query materialized every retained session and therefore did not meet API-036. The repair replaces it with indexed keyset reads, capped at 20 batches of 100 retained rows per request. Active-session filtering occurs within that work bound. If a window contains only expired or revoked rows, its response may be empty while a continuation remains; neither adapter may treat that as the end of the inventory. The service's public timestamp/selector boundary remains usable after the boundary session is revoked. Confirmation and revocation use an indexed owner-and-selector lookup.

Migration 0020 assigns independent random public selectors and adds the required indexes. Existing session credentials and lifetimes are unchanged. Old derived-selector links no longer identify a target; reload the session inventory. The API adds `session-public-id-v2` to its signed cursor filter so older signed positions receive the standard `400 invalid-cursor` response instead of resuming in a different order. Successful sign-ins still have no per-person session cap; the repair bounds each listing request rather than adding an authentication policy.

Added adapter regressions exercise a scan window of 2,000 expired rows followed by the older live caller, rejection of a correctly signed legacy-order cursor, no-JS traversal beyond 25 rows after boundary revocation, confirmation/revocation outside the first page, malformed HTML positions and an empty-page template with a Next link. Independent source review approved the bounded service/repository implementation and the adapter changes separately.

For the bounded repair, production builds of `internal/api` and `internal/web` pass with Go 1.26.11. The actual embedded session templates and catalogue pass all five rendering states under race instrumentation with all production web files (1.242 seconds); the message catalogue race suite also passes (1.027 seconds). Gofmt, diff whitespace, catalogue JSON and OpenAPI YAML checks pass. These focused runs do not execute the SQLite-backed API/HTML behavioral regressions. Full runtime qualification of the combined repair remains a provider gate.
