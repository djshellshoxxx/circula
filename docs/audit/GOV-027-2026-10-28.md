## Implementation scope

- `internal/web/templates/help.html`: a semantic `h2` with ID `support-boundaries`
  explains who handles network rules/trades versus software/deployment/platform
  policy. A support request does not grant data access. Break-glass safeguards
  are stated as policy requirements, with operator procedures and incomplete
  enforcement explicitly distinguished from technical guarantees. Host readability
  and lack of cryptographic separation are explicit.
- `internal/web/templates/admin_home.html`: descriptive link to the existing
  `/help#support-boundaries` location. No new route or business logic.
- `docs/specs/11-deployment-operations.md`: corresponding GOV-027/OPS-031 summary;
  SEC-013 implementation gaps and DEC-014 remain open.
- `internal/web/support_boundaries_template_test.go`: standard-library tests load
  and render the actual template files and check guidance, caveats and the link.

No permission, authentication, role, 24-hour delay, grant-chain, financial policy,
threshold, schema, credential, licence or service-level commitment changed.
