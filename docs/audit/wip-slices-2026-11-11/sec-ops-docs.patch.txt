+# Personal data inventory
+
+Version: 1, 2026-11-04. Specifications: SEC-014 (data minimisation), SEC-017 (exports), SEC-018 (retention and erasure),
+DAT section 9 ([06](../specs/06-data-ledger-audit.md#9-retention)). Derived from the migrations in
+`internal/store/migrations/` (0001 to 0015).
+
+This file is checked by `internal/store/pii_inventory_test.go`. The test migrates an empty database and fails when a
+table column is classified neither under [Personal data columns](#personal-data-columns) nor under
+[Other columns](#other-columns), when this file names a column that no longer exists, or when a personal-data row has an
+empty cell. Adding a migration that adds a column therefore means adding a row here, in the same change.
+
+Retention values are what the current build does. Where the specification gives a recommended default that the build
+does not apply, the cell says so. Retention periods for personal data are an open decision (DEC-020, counsel review,
+RSK-022): nothing here is a compliance claim.
+
+## Forbidden data (SEC-014)
+
+The product collects no national identity number, government identifier, bank account number, card data or date of
+birth. `TestSchemaHasNoForbiddenPersonalData` fails if a column whose name suggests one of them is added. Free-text
+fields can still receive such data if a person types it; their length is limited (FR-016 and the service validators)
+and administrators are told not to write personal data into reasons ([erasure.md](../dev/erasure.md#the-audit-chain)).
+
+## Terms used in the tables
+
+- **Category**: `identifier` (names or sign-in identifiers that point at a person), `credential` (secret
+  authentication material, stored only as a hash or sealed), `profile` (a setting the person chose), `free text`
+  (anything a person typed, which may contain personal data), `activity` (when a person was last active), `governance
+  marker` (a statement about a member made by the network).
+- **Export**: the export packages of [07](../specs/07-api-contract.md) and DAT-037/038. "Network export" is the
+  administrator export of the whole network; "self-export" is a member's export of their own data (SEC-017). Exports
+  never contain credentials, password hashes, token hashes, MFA secrets or recovery material.
+- **Erasure**: what the erasure of a departed member does (`AnonymiseMember`, `EraseMyData`, `circula erase-member`;
+  see [docs/dev/erasure.md](../dev/erasure.md)). "Person erasure" means the person row is also anonymised, which happens
+  only when the person has no other live membership and the request came from the person or the operator CLI. Closed
+  networks are erased the same way after their read-only period (GOV-025). Backups taken earlier keep the old values
+  until backup retention ends (SEC-028).
+

+// personalCategories is the vocabulary of the Category cell in the inventory.
+var personalCategories = map[string]bool{
+	"identifier": true, "credential": true, "profile": true, "free text": true, "activity": true, "governance marker": true,

+// forbiddenWords are column-name words for data SEC-014 forbids collecting:
+// national identity numbers, government identifiers, bank account numbers,

+	"national": true, "ssn": true, "nin": true, "passport": true, "government": true, "taxid": true, "tin": true,

+type inventory struct {
+	personal map[string][]string // "table.column" -> cells after the first
+	other    map[string][]string // table -> columns
+}

+var codeSpan = regexp.MustCompile("`([^`]+)`")
+
+// readInventory parses the two machine-checked tables of the inventory: the
+// section "Personal data columns" (one row per column) and "Other columns"
+// (one row per table listing the remaining columns).
+func readInventory(t *testing.T) inventory {
+	t.Helper()
+	b, err := os.ReadFile(inventoryPath)
+	if err != nil {
+		t.Fatalf("personal-data inventory missing (SEC-014): %v", err)
+	}
+	inv := inventory{personal: map[string][]string{}, other: map[string][]string{}}
+	section := ""
+	for _, line := range strings.Split(string(b), "\n") {
+		if strings.HasPrefix(line, "## ") {
+			section = strings.TrimSpace(strings.TrimPrefix(line, "## "))
+			continue
+		}
+		if !strings.HasPrefix(line, "|") || strings.HasPrefix(line, "|---") {
+			continue
+		}
+		cells := strings.Split(strings.Trim(line, "|"), "|")
+		for i := range cells {
+			cells[i] = strings.TrimSpace(cells[i])
+		}
+		key := codeSpan.FindStringSubmatch(cells[0])
+		if key == nil { // header row
+			continue
+		}
+		switch {
+		case strings.HasSuffix(section, "Personal data columns"):
+			if _, dup := inv.personal[key[1]]; dup {
+				t.Errorf("inventory lists %s twice", key[1])
+			}
+			inv.personal[key[1]] = cells[1:]
+		case strings.HasSuffix(section, "Other columns"):
+			if len(cells) < 2 {
+				t.Fatalf("inventory row for %s has no column list", key[1])
+			}
+			if _, dup := inv.other[key[1]]; dup {
+				t.Errorf("inventory lists table %s twice under Other columns", key[1])
+			}
+			var cols []string
+			for _, m := range codeSpan.FindAllStringSubmatch(cells[1], -1) {
+				cols = append(cols, m[1])
+			}
+			inv.other[key[1]] = cols
+		}
+	}
+	if len(inv.personal) == 0 || len(inv.other) == 0 {
+		t.Fatalf("inventory has no machine-readable tables (personal %d, other %d)", len(inv.personal), len(inv.other))
+	}
+	return inv
+}

+// schemaColumns returns "table.column" for every column of every table after
+// all migrations.
+func schemaColumns(t *testing.T) []string {
+	t.Helper()
+	s := openStore(t)
+	rows, err := s.DB().Query(`SELECT m.name, p.name FROM sqlite_master m JOIN pragma_table_info(m.name) p
+		WHERE m.type = 'table' AND m.name NOT LIKE 'sqlite_%' ORDER BY m.name, p.cid`)
+	if err != nil {
+		t.Fatal(err)
+	}
+	defer func() { _ = rows.Close() }()
+	var out []string
+	for rows.Next() {
+		var tbl, col string
+		if err := rows.Scan(&tbl, &col); err != nil {
+			t.Fatal(err)
+		}
+		out = append(out, tbl+"."+col)
+	}
+	if err := rows.Err(); err != nil {
+		t.Fatal(err)
+	}
+	return out
+}

+// TestPersonalDataInventoryCoversSchema fails when a migration adds a column
+// (or table) that the committed inventory does not classify, or when the
+// inventory names a column that no longer exists (SEC-014 traceability check).
+func TestPersonalDataInventoryCoversSchema(t *testing.T) {
+	inv := readInventory(t)
+	classified := map[string]string{}
+	for col := range inv.personal {
+		classified[col] = "personal"
+	}
+	for tbl, cols := range inv.other {
+		for _, c := range cols {
+			k := tbl + "." + c
+			if prev, ok := classified[k]; ok {
+				t.Errorf("inventory classifies %s twice (%s and other)", k, prev)
+			}
+			classified[k] = "other"
+		}
+	}
+	inSchema := map[string]bool{}
+	var missing []string
+	for _, c := range schemaColumns(t) {
+		inSchema[c] = true
+		if _, ok := classified[c]; !ok {
+			missing = append(missing, c)
+		}
+	}
+	if len(missing) > 0 {
+		t.Errorf("columns not classified in %s (add each to \"Personal data columns\" with purpose, retention, export "+
+			"and erasure, or to \"Other columns\"): %s", inventoryPath, strings.Join(missing, ", "))
+	}
+	var stale []string
+	for c := range classified {
+		if !inSchema[c] {
+			stale = append(stale, c)
+		}
+	}
+	sort.Strings(stale)
+	if len(stale) > 0 {
+		t.Errorf("inventory names columns that are not in the schema: %s", strings.Join(stale, ", "))
+	}
+}

+// TestPersonalDataInventoryRowsComplete requires a category, purpose,
+// retention, export and erasure entry for every personal-data column.
+func TestPersonalDataInventoryRowsComplete(t *testing.T) {
+	inv := readInventory(t)
+	for col, cells := range inv.personal {
+		if len(cells) != 5 {

+// Package logx is the application-log boundary (SEC-020, OPS-032). The HTTP
+// adapters and the serve command log only through a logger wrapped by New or
+// Wrap, which, whatever the underlying slog handler:
+//
+//   - replaces the value of any attribute whose key names a credential
+//     (password, secret, token, session, cookie, CSRF, TOTP, OTP, recovery
+//     code, API key, authorization) with Redacted;
+//   - redacts invitation and API tokens, bearer values and key=value
+//     credentials inside free text, and masks email addresses and
+//     international phone numbers;
+//   - escapes newlines, other control characters, Unicode line separators and
+//     bidirectional or invisible format characters (and the backslash that
+//     introduces an escape), so user-controlled text cannot end an entry,
+//     forge a second one or hide part of a line;
+//   - stamps every entry in UTC.
+//
+// Errors, Stringers and other values are rendered to text and cleaned the
+// same way. Integers, booleans, durations and times pass unchanged.
+package logx
+
+import (
+	"context"
+	"fmt"
+	"log/slog"
+	"regexp"
+	"strings"
+	"unicode"
+	"unicode/utf8"
+)
+
+// Redacted replaces the value of a sensitive attribute.
+const Redacted = "[REDACTED]"
+
+// New returns l (slog.Default() when nil) with its handler wrapped by Wrap.
+// A logger that is already wrapped is returned unchanged.
+func New(l *slog.Logger) *slog.Logger {
+	if l == nil {
+		l = slog.Default()
+	}
+	if _, ok := l.Handler().(*handler); ok {
+		return l
+	}
+	return slog.New(&handler{inner: l.Handler()})
+}
+
+// Wrap returns h behind the redacting, escaping handler. Wrapping twice adds
+// no second layer.
+func Wrap(h slog.Handler) slog.Handler {
+	if _, ok := h.(*handler); ok {
+		return h
+	}
+	return &handler{inner: h}
+}
+
+type handler struct{ inner slog.Handler }
+
+func (h *handler) Enabled(ctx context.Context, l slog.Level) bool { return h.inner.Enabled(ctx, l) }
+
+func (h *handler) Handle(ctx context.Context, r slog.Record) error {
+	out := slog.NewRecord(r.Time.UTC(), r.Level, Clean(r.Message), r.PC)
+	r.Attrs(func(a slog.Attr) bool {
+		out.AddAttrs(cleanAttr(a))
+		return true
+	})
+	return h.inner.Handle(ctx, out)
+}
+
+func (h *handler) WithAttrs(as []slog.Attr) slog.Handler {
+	clean := make([]slog.Attr, len(as))
+	for i, a := range as {
+		clean[i] = cleanAttr(a)
+	}
+	return &handler{inner: h.inner.WithAttrs(clean)}
+}
+
+func (h *handler) WithGroup(name string) slog.Handler {
+	return &handler{inner: h.inner.WithGroup(Clean(name))}
+}
+
+func cleanAttr(a slog.Attr) slog.Attr {
+	key := Clean(a.Key)
+	if sensitiveKey(a.Key) {
+		return slog.String(key, Redacted)
+	}
+	v := a.Value.Resolve()
+	switch v.Kind() {
+	case slog.KindString:
+		return slog.String(key, Clean(v.String()))
+	case slog.KindTime:
+		return slog.Time(key, v.Time().UTC())
+	case slog.KindGroup:
+		g := v.Group()
+		out := make([]slog.Attr, len(g))
+		for i, x := range g {
+			out[i] = cleanAttr(x)
+		}
+		return slog.Attr{Key: key, Value: slog.GroupValue(out...)}
+	case slog.KindAny:
+		// fmt recovers from a panicking Error or String method.
+		return slog.String(key, Clean(fmt.Sprintf("%+v", v.Any())))
+	default:
+		return slog.Attr{Key: key, Value: v}
+	}
+}

+// sensitiveFragments mark a credential when they appear anywhere in the key
+// (lower-cased, separators removed); sensitiveWords only as a whole word.
+var (
+	sensitiveFragments = []string{"password", "passwd", "passphrase", "secret", "token", "csrf", "xsrf", "session",
+		"cookie", "authorization", "bearer", "totp", "credential", "apikey", "privatekey", "recoverycode"}
+	sensitiveWords = map[string]bool{"otp": true, "sid": true, "pwd": true, "pw": true, "auth": true}
+	keyWord        = regexp.MustCompile(`[^a-z0-9]+`)
+)
+
+func sensitiveKey(k string) bool {
+	lower := strings.ToLower(k)
+	joined := keyWord.ReplaceAllString(lower, "")
+	for _, f := range sensitiveFragments {
+		if strings.Contains(joined, f) {
+			return true
+		}
+	}
+	for _, w := range keyWord.Split(lower, -1) {
+		if sensitiveWords[w] {
+			return true
+		}
+	}
+	return false
+}

+	credentialKV = regexp.MustCompile(`(?i)((?:password|passwd|passphrase|secret|token|csrf|xsrf|session(?:[_-]?id)?|cookie|` +
+		`totp|otp|recovery[_ -]?codes?|api[_-]?key|authorization)"?\s*[=:]\s*)("[^"]*"|'[^']*'|[^\s"',;&]+)`)
+	email = regexp.MustCompile(`[A-Za-z0-9._%+-]+@[A-Za-z0-9-]+(?:\.[A-Za-z0-9-]+)*\.[A-Za-z]{2,}\b`)
+	phone = regexp.MustCompile(`\+\d[\d ().-]{6,}\d`)
+)
+
+// Clean returns s with credentials redacted, email addresses and
+// international phone numbers masked, and every character that could break
+// or disguise a log line escaped (\n, \r, \t, \xNN, \uNNNN; a backslash
+// becomes \\). Text that needs none of this is returned unchanged.
+func Clean(s string) string {
+	s = bearerToken.ReplaceAllString(s, "${1}_REDACTED")
+	s = bearerValue.ReplaceAllString(s, "${1} "+Redacted)
+	s = credentialKV.ReplaceAllString(s, "${1}"+Redacted)
+	s = email.ReplaceAllString(s, "[email]")
+	s = phone.ReplaceAllString(s, "[phone]")
+	if !needsEscape(s) {
+		return s
+	}
+	var b strings.Builder
+	b.Grow(len(s) + 16)
+	for i := 0; i < len(s); {
+		r, n := utf8.DecodeRuneInString(s[i:])
+		switch {
+		case r == utf8.RuneError && n <= 1:
+			b.WriteString(`\ufffd`)
+		case r == '\\':
+			b.WriteString(`\\`)
+		case r == '\n':
+			b.WriteString(`\n`)
+		case r == '\r':
+			b.WriteString(`\r`)
+		case r == '\t':
+			b.WriteString(`\t`)
+		case r < 0x80 && unicode.IsControl(r):
+			fmt.Fprintf(&b, `\x%02x`, r)
+		case unsafeRune(r):
+			fmt.Fprintf(&b, `\u%04x`, r)
+		default:
+			b.WriteString(s[i : i+n])
+		}
+		i += n
+	}
+	return b.String()
+}
+
+// unsafeRune reports runes outside ASCII that end or disguise a line: C1
+// controls (including NEL), line and paragraph separators, and format
+// characters such as bidirectional overrides and zero-width joiners.
+func unsafeRune(r rune) bool {
+	return unicode.IsControl(r) || unicode.In(r, unicode.Zl, unicode.Zp, unicode.Cf)
+}
+
+func needsEscape(s string) bool {
+	for i := 0; i < len(s); i++ {
+		if c := s[i]; c < 0x20 || c == 0x7f || c == '\\' || c >= 0x80 {
+			if c >= 0x80 {
+				return needsEscapeUnicode(s[i:])
+			}
+			return true
+		}
+	}
+	return false
+}
+
+func needsEscapeUnicode(s string) bool {
+	for i := 0; i < len(s); {
+		r, n := utf8.DecodeRuneInString(s[i:])
+		if (r == utf8.RuneError && n <= 1) || r < 0x20 || r == 0x7f || r == '\\' || unsafeRune(r) {
+			return true
+		}
+		i += n
+	}
+	return false
+}

+// parseRules reads the rule file. It accepts the layout the shipped file uses
+// (groups, rules, expr as a block or inline scalar, labels, annotations), not
+// arbitrary YAML; promtool, when installed, checks the full syntax.
+func parseRules(t *testing.T, path string) []alertRule {
+	t.Helper()
+	b, err := os.ReadFile(path)
+	if err != nil {
+		t.Fatalf("alert rules missing (OPS-015): %v", err)
+	}
+	var rules []alertRule
+	var cur *alertRule
+	group, section, block := "", "", false
+	unquote := func(v string) string {
+		v = strings.TrimSpace(v)
+		if len(v) >= 2 && (v[0] == '"' && v[len(v)-1] == '"' || v[0] == '\'' && v[len(v)-1] == '\'') {
+			return v[1 : len(v)-1]
+		}
+		return v
+	}
+	for _, line := range strings.Split(string(b), "\n") {
+		trim := strings.TrimSpace(line)
+		indent := len(line) - len(strings.TrimLeft(line, " "))
+		if block {
+			if trim == "" || indent > 8 {
+				cur.expr += trim + "\n"
+				continue
+			}
+			block = false
+		}
+		if trim == "" || strings.HasPrefix(trim, "#") {
+			continue
+		}
+		key, val, _ := strings.Cut(strings.TrimPrefix(trim, "- "), ":")
+		val = strings.TrimSpace(val)
+		switch {
+		case indent == 2 && strings.HasPrefix(trim, "- name:"):
+			group = unquote(val)
+		case indent == 6 && strings.HasPrefix(trim, "- "):
+			rules = append(rules, alertRule{group: group, labels: map[string]string{}, annotations: map[string]string{}})
+			cur = &rules[len(rules)-1]
+			section = ""
+			if key == "alert" {
+				cur.name = unquote(val)
+			} else {
+				cur.name = "record " + unquote(val)
+			}
+		case cur != nil && indent == 8:
+			section = ""
+			switch key {
+			case "expr":
+				if val == "|" || val == ">" || val == "|-" || val == ">-" {
+					block = true
+				} else {
+					cur.expr = val
+				}
+			case "for":
+				cur.forDur = val
+			case "labels", "annotations":
+				section = key
+			}
+		case cur != nil && indent == 10 && section == "labels":
+			cur.labels[key] = unquote(val)
+		case cur != nil && indent == 10 && section == "annotations":
+			cur.annotations[key] = unquote(val)
+		}
+	}
+	return rules
+}

+// seriesIn returns the metric and recording-rule names a PromQL expression
+// reads: identifiers that are not keywords, not function calls and not part of
+// a number or duration.
+func seriesIn(expr string) []string {
+	e := promString.ReplaceAllString(expr, `""`)
+	e = promMatchers.ReplaceAllString(e, " ")
+	e = promRange.ReplaceAllString(e, " ")
+	e = promLabelArg.ReplaceAllString(e, " ")
+	var out []string
+	for _, loc := range promIdent.FindAllStringIndex(e, -1) {
+		if loc[0] > 0 && strings.ContainsRune("0123456789.", rune(e[loc[0]-1])) { // 5m, 1e3, 0.8
+			continue
+		}
+		if strings.HasPrefix(strings.TrimLeft(e[loc[1]:], " \t\n"), "(") { // a function call
+			continue
+		}
+		if id := e[loc[0]:loc[1]]; !promKeywords[strings.ToLower(id)] {
+			out = append(out, id)
+		}
+	}
+	return out
+}

+# Incident response procedure
+
+Version 1, 2026-11-04. Specifications: SEC-030 (incident response), OPS-030 (support tiers and severity), OPS-015
+(alerts), OPS-033 (failure modes). Related: SEC-013 (break-glass), GOV-023 and GOV-024 (suspension), DAT section 10.2
+(repair), DEC-014 (notice period), DEC-022 (support objectives), RSK-026 (breach notification duties).
+
+**Status.** This is the written procedure SEC-030 requires. The response targets in
+[Severity levels](#severity-levels) are recommendations: they are not service-level commitments and must not be
+presented as such until the platform operator approves them (DEC-022, open). The deadline for notifying affected
+parties is set by DEC-014 and counsel review (RSK-026); this document does not assert one. A tabletop drill is still
+to be run and recorded before hosted launch ([Drills](#drills)).
+
+Names of the people who hold each role are kept outside this repository, with the alert routing.
+
+## Severity levels
+
+The same three levels apply to incidents and to support requests. Alerts carry the level in their `incident_level`
+annotation ([alerts/circula.rules.yml](alerts/circula.rules.yml)); [monitoring.md](monitoring.md#alerts-ops-015) and the
+[runbook](runbook.md#incident-contacts-and-severity) use the same names.
+
+| Level | Meaning | Examples | Recommended first response (DEC-022 open) | Recommended restore target (DEC-022 open) | Channel |
+|---|---|---|---|---|---|
+| `critical` | Ledger integrity or security is at risk, or the instance is down | Ledger verification failure or a frozen network; suspected exposure of credentials, keys or personal data; an authorisation fault; audit anchor mismatch; instance down; migration failure | Within 1 hour of the alert, at any time | Contained at once (a failing network freezes automatically); serving again within the recovery time objective, 4 hours as proposed in [rpo-rto.md](rpo-rto.md) (DEC-016) | Paging route for `severity="critical"` alerts to the on-duty platform operator; the private security channel in [SECURITY.md](../../SECURITY.md) for vulnerability reports |
+| `high` | One network cannot post, or a safeguard is degraded while trading continues | Posting refused for a network for a reason other than integrity; backup stale; volume above 80 percent; sustained authentication throttling | Within 4 hours, during the operator's working hours | 1 working day | Team alert route for `severity="warning"` alerts; incident ticket |
+| `normal` | Other faults and support requests | A failed scheduled job; a user interface defect; a question from a network administrator | 3 working days (the acknowledgement target in [SECURITY.md](../../SECURITY.md)) | Next planned release, or as agreed with the requester | Ticket or issue tracker; network administrators use their usual contact with the operator |
+
+Approved targets (record here when the platform operator decides DEC-022):
+
+| Level | Approved first response | Approved restore target | Approved by and date |
+|---|---|---|---|
+| `critical` | not set | not set | DEC-022 open |
+| `high` | not set | not set | DEC-022 open |
+| `normal` | not set | not set | DEC-022 open |
+
+When in doubt, choose the higher level. A ledger or security incident is always `critical`. The incident lead may
+raise or lower the level as facts arrive and records each change.
+
+## Roles
+
+| Role | Responsibility during an incident |
+|---|---|
+| Incident lead (the on-duty platform operator unless handed over) | Declares the incident, sets and changes the level, coordinates, keeps the incident record and the timeline, decides when the incident is closed |
+| Platform operator | Containment and recovery on the host: freeze, maintenance mode, suspension, secret rotation, backups, restore, verification |
+| Product architect | Decides on every ledger finding and repair (DAT section 10.2); a ledger incident is not closed without their agreement |
+| Security owner | Leads security incidents: scope of exposure, secret rotation, vulnerability handling under [SECURITY.md](../../SECURITY.md), the question to counsel |
+| Network administrators of each affected network | Receive the operator's notice, notify their members, take network-level decisions (for example suspending trading, GOV-023) |
+| Counsel | Advises on notification duties to regulators and individuals and their deadlines (RSK-026, DEC-014) |

+## Detection sources
+
+- Alerts: [monitoring.md](monitoring.md#alerts-ops-015) lists them; the Prometheus rules are in
+  [alerts/circula.rules.yml](alerts/circula.rules.yml).
+- Ledger verification: the hourly `verify` job, every start, every backup, `circula verify-ledger`, and the
+  administrators' consistency check. A failure logs "network frozen" and sets `circula_frozen_networks`.
+- Audit chain: `circula audit-anchor verify` exit `3` ([runbook.md](runbook.md#audit-anchor-rb-010)).
+- Application logs: error entries such as `api internal error` and `web internal error`. Users see the request id as
+  the "reference" on error pages; search the logs for it.
+- Reports: abuse reports from members, requests from network administrators, vulnerability reports under
+  [SECURITY.md](../../SECURITY.md).
+- The audit trail: unexpected administrative or break-glass events (SEC-013).

+## Procedure
+
+### 1. Declare and classify
+
+Open an incident record (outside this repository) with: time detected (UTC), source, level, incident lead, affected
+networks (by slug), and a timeline that every participant appends to. Use [Severity levels](#severity-levels).
+
+### 2. Contain
+
+- **Ledger verification failure.** The failing network is frozen automatically: its writes are refused (API `423
+  network-frozen`, web "Network read-only"), reads and exports work, other networks keep serving. Do not edit the
+  database and do not auto-correct. If the cause may affect every network, put the instance in maintenance mode:
+  `circula maintenance -config ... on`.
+- **Security incident.** Limit the exposure first:
+  - Revoke the access of an affected person: `circula reset-password -login NAME -reason ...` ends every session, API
+    token and recovery code of that person; `circula reset-mfa` also removes the second factor. This build has no
+    command that ends every session of the instance: if that is needed, keep `serve` stopped while the affected
+    people are reset one by one.
+  - Rotate any secret that may be exposed: the six secrets in [configuration.md](configuration.md#secrets), the web
+    signing key ([configuration.md](configuration.md#runtime-state-the-web-signing-key-sec-027)) and the TLS key. Read
+    what each rotation invalidates there before rotating it.
+  - If a network must stop trading while the incident lasts: `circula suspend start -network <slug> -category
+    security_incident -reason "..." -operator "<name>"` ([runbook.md](runbook.md#suspending-a-network-gov-024)). Members keep
+    read and export access; the network's administrators are notified in their inbox and audit log.
+  - Close any break-glass session that is not needed: `circula break-glass list -network <slug>`, then
+    `circula break-glass close -session ID -reason "..."`.
+- **Loss of service.** Follow the failure-mode table in [monitoring.md](monitoring.md#failure-modes-ops-033).
+
+### 3. Preserve evidence
+
+Before any recovery step:
+
+1. Take a backup of the current state: `circula backup /var/backups/circula/incident-<id>.db` (works while `serve` runs).
+   A backup whose ledger verification fails is still written and is evidence.
+2. Keep the damaged database file if `serve` was stopped because of corruption; do not overwrite it.
+3. Copy the application logs covering the incident window, the audit mirror file if configured, and the newest audit
+   anchor to storage the incident lead controls. Logs contain no credentials by design (SEC-020); treat them as
+   restricted anyway (SEC-021).
+4. Capture the findings: `circula verify-ledger -network <slug>` (stop `serve` first), and the output of any
+   consistency check.
+5. Record hashes (`sha256sum`) of the preserved files in the incident record.
+
+### 4. Notify
+
+1. **Affected network administrators first.** The operator notifies the administrators of each affected network, and
+   only of that network, with: what happened, what is affected, what was done, what members may notice, and the next
+   update time. The deadline is set by DEC-014 and counsel review; it is not asserted here. For a platform suspension
+   the software already sends an inbox notice (GOV-024).
+2. **Members through their administrators.** The operator does not contact members directly. Administrators inform
+   their members, for example with a network announcement.
+3. **Regulators and individuals** only as counsel advises (RSK-026).
+4. For hosted deployments, the published practice is [docs/platform/incident-notification.md](../platform/incident-notification.md).
+
+### 5. Recover and verify
+
+- Restore only from a verified backup whose `ledger_verification.status` is `ok`
+  ([backup-restore.md](backup-restore.md#restoring)), or correct through new ledger transactions (reversal or adjustment
+  with dual control). Never edit ledger entries. A direct data change is allowed only as DAT section 10.2 states.
+- After any restore or repair: run `circula verify-ledger` (exit `0`), `circula audit-anchor verify` against the newest
+  anchor, start `serve`, and check `/readyz`. A frozen network thaws on the next passing verification.
+- Confirm with the affected network administrators that balances and recent trades look right; reconcile any gap
+  between the backup and the incident (trades made after the backup must be re-entered by the members).
+- Record the measured recovery time against the objective in [rpo-rto.md](rpo-rto.md).
+
+### 6. Close and review
+
+The incident lead closes the incident when service is restored, the ledger verifies and notifications are done. Within
+the following two weeks, write a blameless post-incident review: timeline, cause, what worked, what did not, and
+actions with owners. Keep it in the operator's incident register, give it to the affected network administrators, and
+add follow-up defects to `docs/qa/DEFECTS.md` or the issue tracker without personal data.

+## Application logs (SEC-020, OPS-032)
+
+Logs are structured: `log-format=json` (default) writes one JSON object per line, `text` one `key=value` line. Every
+entry has `time` (UTC), `level`, `msg` (the event name, for example `request`, `api internal error`,
+`web internal error`, `scheduled job failed`) and, for entries about a request, `request_id`. The UI and the API keep
+the `X-Request-Id` the edge assigned, so the request id on an error page ("reference") finds both the access-log entry
+and the error entry.
+
+Everything `serve` logs goes through `internal/logx`, which:
+
+- replaces the value of any field whose name refers to a password, secret, token, session, cookie, CSRF token, TOTP or
+  OTP, recovery code, API key or authorization with `[REDACTED]`;
+- removes invitation and API tokens, bearer values and `key=value` credentials from free text such as error messages,
+  and masks email addresses and international phone numbers;
+- escapes newlines, other control characters, Unicode line separators and bidirectional or invisible format
+  characters, so text a user typed cannot end an entry or forge another one.
+
+The access log records method, route template, status and duration; never the path, query, headers or body. Monetary
+amounts and balances are not logged; they are in audit events. Tests: `internal/logx`, `TestLogsCarryNoCanaryAcrossFlows`
+(`internal/web`), `TestAPILogForgeryAndCredentialsInErrors` (`internal/api`), `TestAccessLogCarriesNoCredentials`
+(`cmd/circula`). `log-level` needs a restart to change ([configuration.md](configuration.md)).
