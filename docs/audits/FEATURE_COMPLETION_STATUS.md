## Classification and full inventory

“Complete and verified” requires implementation and matching execution evidence for the stated scope. “Implemented but insufficiently tested” includes a reviewed implementation whose current-head runtime gate is pending. “Partially implemented” names missing behavior; “broken” requires a demonstrated defect; “not started,” “superseded” and “blocked by dependencies” are distinct states. An owner-policy choice is not an engineering implementation.

The full core requirement inventory is [TRACEABILITY.md](../TRACEABILITY.md), with source/test citations for 531 IDs (502 requirements plus 29 decision-register entries). The [45-row beta matrix](../plans/circula-completion-matrix.md) groups user flows but does not replace that larger inventory. [The branch matrix](BRANCH_CONSOLIDATION_MATRIX.md) covers historical specifications and alternative implementations, including conflicting definitions archived instead of adopted. Status notes in old specification tables are declarations with known stale text, not current execution results. This audit does not calculate a completion percentage from them.
