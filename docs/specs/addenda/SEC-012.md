# SEC-012 addendum: account security notices

Status: partly implemented (migration 0003). Scope of this addendum: notices for credential and second-factor changes to a person's own account. Network administrative actions already audit via `s.audit`; member-facing notices for those are not part of this change.

## Decisions

- Table `security_notices(id, person_id, kind, created_at, seen_at, detail)`. Written in the same write unit as the change and its audit event (`Service.notify`), so a rollback leaves no notice.
- Kinds: `password.changed`, `mfa.enabled`, `mfa.disabled`, `mfa.recovery_codes_regenerated`, `mfa.recovery_code_used`, `token.created` (detail: token name), `token.revoked`.
- Service: `ListSecurityNotices(actor, unseenOnly)` (own notices only, newest first, max 100), `CountUnseenSecurityNotices`, `AckSecurityNotices` (marks all of the caller's unseen notices seen). Acknowledging is not audited: it changes no right, credential or balance.
- Web: `/account/security` lists notices and manages MFA; the header shows a "Security (N new)" link on every signed-in page via `page.SecUnseen` (one extra count query per rendered page).
- Detail never carries secrets; only the token name chosen by the person.

## Acceptance to tests

| Criterion | Test |
|---|---|
| Notice on password change, token create/revoke, MFA on/off, recovery regen/use | `service.TestSecurityNotices`, `TestRecoveryCodes`, `TestDisableMFA`, `TestRegenerateRecoveryCodes` |
| Notices are private to the person | `service.TestSecurityNotices` (cross-person list and ack), `TestMFAAuthzScopes` |
| Banner and acknowledge | `web.TestWebSecurityNoticesAndDisable` |

## Known gaps

- No retention purge of old notices (grow with account activity; small). Add to `Purge` later.
- Notices are shown in the web UI only; no email or push (no verified contact channel yet, DEC-009).
- Not covered: notice to a member when an administrator changes their rights or balance (the rest of SEC-012).
- Notices for a person reset through account recovery (another work item) should call `Service.notify` in the same unit.
