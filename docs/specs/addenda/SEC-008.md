# SEC-008 addendum: account recovery without email

Status: implemented (migration 0004), with the deviations listed below. This
addendum does not edit `docs/specs/09-security-privacy.md`; the spec owners
decide how to fold it in. Operator runbook: `docs/dev/recovery.md`.

## Context

The spec asks for recovery over a verified contact channel (DEC-009). Circula
stores no email address, so that channel does not exist. This addendum defines
the channel-free replacement: pre-issued single-use recovery codes, plus an
administrator-assisted and an operator-assisted reset.

## Decisions

1. **Recovery codes.** A signed-in person (password required, full-scope
   session or token) generates 10 codes. Each is 80 bits of randomness, shown
   once as `XXXX-XXXX-XXXX-XXXX`, stored as salted SHA-256
   (`sha256("circula/recovery/v1\0"+person_id+"\0"+code)`), single use.
   Regenerating deletes the old batch in the same unit of work. Table
   `account_recovery_codes` is separate from any MFA recovery table.
2. **Self-service reset** `RecoverPassword(login, code, newPassword)`:
   throttled per login under the key `"recover: "+login` (the space cannot
   occur in a login, so it never collides with a real login's own counter),
   escalating lock identical to Login (5 free attempts, then 15 min doubling to
   24 h); attempts are counted before evaluation; unknown login, malformed code,
   wrong code and used code return the same `unauthenticated` error after the
   same Argon2 work; the code is consumed with a conditional `UPDATE`, so of N
   parallel uses exactly one wins. Success sets the password, clears
   must_change_password, revokes ALL sessions and ALL API tokens, deletes the
   remaining codes (a code in the wrong hands means the sheet may be exposed),
   clears the login's throttles and writes `person.recovered`. It signs nobody
   in.
3. **Admin-assisted reset** `AdminResetPassword(actor, netID, memberID, reason)`:
   administrator of the network (or System actor) resets an ACTIVE member of
   the same network. Returns a random 120-bit temporary password, shown once.
   Sets must_change_password, revokes all sessions, tokens and recovery codes
   of the target. Guards: cannot reset oneself (member or person identity);
   target outside the network (including another network's member) is
   not-found; reason mandatory; 10 successful resets per admin per rolling hour;
   resetting another administrator is allowed but audited with
   `high_risk:true`. Audit: `member.password_reset` in the network chain
   (actor = admin member, reason, subject = member) and
   `person.password_reset` in the platform chain.
4. **Operator reset** `OperatorResetPassword(SystemActor, login, reason)` via
   `circula reset-password -login X -reason "..."`. Same effects, platform
   audit event with actor type `platform_operator` and the reason. Needs the
   database lock (stop `serve`), like `admin create-operator`.
5. **Forced change.** `persons.must_change_password`. `Authenticate` and
   `AuthenticateToken` set `Actor.MustChangePassword`. Central enforcement:
   `Actor.Can(ScopeWrite)` is false while the flag is set and
   `principal.open()` returns `password-change-required` (HTTP 403) for write
   scope; the four service entry points that check the scope directly
   (CreateNetwork, joinableActor, CreateAPIToken, RevokeAPIToken) and
   GenerateRecoveryCodes return the same code. `ChangePassword` is the one
   write that works (the scope is judged without the flag, so a read-only token
   cannot use it as a back door) and clears the flag. Logout does not go
   through the service scope check. Reads stay allowed. The web adapter
   redirects every authenticated page except `/account/password` to that page.
6. **Web.** `GET/POST /recover`, `GET/POST /account/recovery-codes`,
   `GET/POST /n/{slug}/admin/members/{id}/reset-password` (confirm page with
   mandatory reason, then a one-time page with the temporary password).
   `Cache-Control: no-store` already applies to every page.

## Deviations from the spec text (decision needed from spec owners)

| Spec | This implementation | Why / residual risk |
|---|---|---|
| SEC-008: verified contact channel, 60 minute token | Pre-issued codes, no expiry | No channel exists. Codes are only as safe as where the person keeps them. |
| SEC-008: notice to previous contact | None | No contact. Mitigation: all sessions and tokens end, so the owner notices at next use; audit events exist. |
| SEC-008 / SEC-011: admin-assisted recovery needs a second approver | One administrator, with reason, rate limit and `high_risk` flag for admin targets | Dual control not built. A lone malicious administrator can take over an ordinary member's login. Follow-up: route reset through SEC-011 approvals when that exists. |
| SEC-008 / SEC-013: operator must not reset directly except break-glass | CLI reset by the operator, audited with reason | Required for the "everyone lost everything" case. Operators already hold the database. |
| SEC-008: no interface shows a new password after issue | The temporary password is shown exactly once to the issuing administrator or operator and never stored in plain text or logged | A one-time display is inherent to out-of-band hand-over. |

## Acceptance criteria and tests

| Criterion | Test |
|---|---|
| Used code rejected on reuse | `TestRecoverReplay` (service), `TestWebRecoveryFlow` |
| Regenerating invalidates old codes | `TestRecoveryCodesGenerate` |
| Codes hashed at rest, not in audit, shown once | `TestRecoveryCodesGenerate`, `TestWebRecoveryFlow` |
| Wrong codes throttled, lock beats a right code, login unaffected | `TestRecoverThrottle` |
| Unknown login indistinguishable (error, lock behaviour, web page) | `TestRecoverUnknownLoginIndistinguishable`, `TestWebRecoveryFlow` |
| Recovery revokes all sessions and tokens, weak password does not burn a code | `TestRecoverRevokesEverything` |
| Parallel use of one code: exactly one winner | `TestRecoverCodeRace` |
| Forced change enforced on service and API; ChangePassword clears; read-only token cannot abuse it | `TestForcedPasswordChange`, `TestForcedPasswordChangeOnAPI` |
| Self reset refused; non-admin refused; cross-network admin cannot reset; departed member refused; reason required; admin target is high risk | `TestAdminResetGuards` |
| 10 per hour per administrator | `TestAdminResetRateLimit` |
| Operator reset: system actor only, audited with reason, codes revoked | `TestOperatorReset`, `TestResetPasswordCommand` |
| Web forced-change redirect, one-time temporary password page | `TestWebAdminReset` |

## Merge notes

- Migration `0004_recovery.sql` assumes `0003` (MFA, another change) exists;
  the loader requires contiguous versions.
- New store interface `RecoveryRepo` (`internal/store/recovery_iface.go`) is
  embedded into `Tx` by one line in `iface.go`.
- `Actor` gains `MustChangePassword`; a login MFA challenge (other change)
  should run before a session exists, so it does not interact with this flag.
- Throttle keys `"recover: <login>"` and `"recgen: <person id>"` live in
  `login_throttle` and are purged by the existing stale-throttle job.
