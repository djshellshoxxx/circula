# Addendum: OPS-019 / SEC-028 backup encryption at rest

Status: implemented. Operator guide: [backup-restore.md](../../ops/backup-restore.md#encryption-at-rest-ops-019-sec-028).

## Decisions

- Standard library AES-256-GCM, streamed in 64 KiB chunks; `golang.org/x/crypto/argon2` only for passphrase keys.
- Container: `CIRCBK1` | kdf id | chunk size | salt(16) | nonce prefix(8), then chunks. Nonce = prefix || 32-bit counter.
  AAD = header || 64-bit chunk index || final flag, so bit flips, reorder, duplication, truncation (also at a chunk
  boundary) and appended data fail authentication. The reader distinguishes "wrong key", "truncated" and "trailing data".
- Key: secret `backup-encryption-key` (env or `backup-encryption-key-file`, 0600). 32 random bytes in base64
  (`circula keygen`) use HKDF-SHA-256 with the per-file salt; anything else (16+ characters) uses Argon2id (t=3, 64 MiB, p=4).
  It must differ from `backup-key` (the HMAC key stays unchanged and independent).
- Plaintext exists only as a `VACUUM INTO` copy in a `0700` `.circula-bk-*` directory beside the destination; it is
  overwritten and removed on every exit path, and stale directories (> 1 h) from killed processes are swept.
  Overwrite is best effort on COW file systems and SSDs (documented).
- Manifest: `encrypted`, `cipher`, `plaintext_bytes`, `plaintext_sha256`; `bytes`/`sha256` are the ciphertext. The HMAC
  covers the new fields only for encrypted backups, so older manifests still verify and flipping `encrypted` off breaks
  the signature. Files are `*.db.enc` (listing and pruning understand both suffixes), mode 0600.
- Write-time proof: the ciphertext is decrypted back in memory and compared to the verified plaintext digest before rename.
- `backup-require-encryption`: restore refuses plaintext backups; backup refuses to run without a key; config is invalid
  when set without a key. Without it, plaintext backups still restore (upgrade path).
- Not done: age/X25519 recipients (out of scope), a separate `backup-verify` command (none exists; `restore` verifies).

## Gaps

- Restore writes the decrypted copy to `<db>.restore-partial` (0600, in the database directory) before the checks; it is
  securely removed when decryption fails and removed by the existing failure paths otherwise.
- Key rotation is manual (re-backup under the new key); no in-place re-encryption command.
