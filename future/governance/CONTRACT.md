# Isolated governance contract

Integration is HOLD. Construct Service with an explicit host-owned SQLite DB, a server clock and Authority. No database is opened, no endpoint registered and no background worker started by importing this module. Only future/governance files exist in this change. No policy, ledger, credit, role or QuietVote writer is exposed.

Use Go 1.26.11. The test-only driver is modernc.org/sqlite v1.60.1. The host must enable SQLite foreign_keys on **every connection** (the service fails closed without it), set a bounded busy timeout, and use the existing single-process-per-file write/backup rules. Authority callbacks receive the exact SQL transaction; production membership, network opt-in, admin/MFA and electorate reads must use that transaction or a provably consistent core-store adaptation. Returning client-supplied role/membership flags is prohibited.

Authority.Principal must return current active membership, network-enabled state and current administrative authority. Default zero fields deny access. Authority.Electorate supplies the active opening-time eligible member IDs, bounded to 10,000. It is frozen on open. Current activity remains necessary on every ballot, even if a voter appears in that snapshot. Authority.PolicyExists is strictly read-only and must accept only same-network, already-created authorized policy versions. It never applies a policy.

Execute accepts Command actions create, edit, open, vote, withdraw, close, comment, hide, dispute, resolve, certify and link. Intent is required and scoped to actor/network; identical retries return the persisted reply, changed payloads conflict. Reads of current principal still run before replay. One distinct ballot per network/proposal/member is enforced by SQLite; no ballot replacement is offered. Ballots and comments do not increment proposal revision; question lifecycle edits do. Draft edits require author and matching revision. Opening freezes content, close time and electorate; duration is bounded to 90 days and opening at most one year ahead. Proposal timestamps use UTC; supplied open/close values are interpreted as absolute instants. Closed results are immutable counts, with separate certification and policy references. No quorum/pass rule is invented by this module.

Read returns the current member's ballot only, visible comments and own/admin dispute details. Other ballots and the eligibility roster have no member API. Drafts are author/admin visible. Operators with database access can read choices: no anonymous, secret, coercion-resistant or one-human uniqueness claim is made. Hidden comment text is erased from its content row; audit retains only action references and moderation/withdrawal/resolution reasons, not a duplicate of the original comment text.

Any active member can record a bounded process concern. Unresolved disputes prevent certification. The challenged member and reporting member cannot resolve that dispute. A certifier cannot be the proposal author or anyone challenged in its dispute history. These are deliberately conservative conflict rules; production adaptation must preserve them or explicitly review changes. Certification does not establish cryptographic proof and cannot change the counts or apply policy. A certified result may link once to an already-applied same-network policy version through an authorized admin operation.

Web is an **unregistered** GET/POST handler. WebAuth authenticates and checks cookie CSRF on every mutation; body limiting is installed before that callback. It must bind X-Network to the authenticated network and never trust a user header as identity. JSON commands require matching Idempotency-Key and Intent. Native forms carry their intent and host CSRF token, and use POST/Redirect/GET. Responses are no-store; JSON errors use RFC 9457 shape. Listing uses a stable ID keyset whose HMAC cursor binds member/network; cursor key is injected and must contain at least 32 secret bytes. Read-only JSON, escaped no-JS forms, votes, results, lifecycle, comment/dispute/admin actions and linked errors are provided. RunCLI delegates to the same authenticated service and bounds command JSON to 64KiB; it neither obtains nor stores credentials.

Public input limits are bytes: title 200, context 12,000, category 64, comments 2,048, withdrawal/moderation reason 1,000, dispute/resolution 2,000; identifiers 128. Labels reject controls/bidi-formatting characters, body text permits newline only among controls. There is no external URL fetch, attachment, arbitrary markup or script dependency. Native radio fields have no preselected choice, explicit label association, legend and hint. Manual keyboard/screen-reader and real-browser qualification remain pending.

## Audit-qualified reference boundaries

Every reference service transaction first takes a checked schema-row SQLite writer lock before mutable authority reads; callbacks must use that supplied transaction and must not perform remote network I/O. Production adapters must qualify this serialization and bounded busy timeout against the core store. Migration verifies the exact module table/index definitions and quoted constraint literals, not just names/version. Each mutation requires one persisted affected row.

Retained-history limits are 100 proposals per member (including withdrawn/closed), 10,000 normal recorded intents per member, 100 comments per member/proposal with a 1,000 total, and 10 disputes per member/proposal with a 100 total. Only one unresolved concern per reporter/challenged-member pair is allowed. Freshly authorized withdraw/hide/resolve/close/certify/link operations remain available at normal intent saturation and still obey lifecycle/conflict checks. An open proposal cannot be withdrawn at or after its deadline. Hidden-content operations do not append repeated fresh hide acknowledgments.

HTTP/CLI input remains 64 KiB. Stored JSON is independently bounded to 128 KiB so escaped valid text within documented field limits remains readable. Duplicate JSON names/case aliases, invalid Unicode/surrogates, unknown fields, excess depth and trailing data fail closed. CLI list accepts an optional AFTER_ID for explicit keyset continuation. Published governance history is retained; no API deletes ballots or rewrites certified outcomes.

## Master HTTP corrections

Raw query bytes are capped at 8192 before authentication. Only one each of proposal, format and cursor is accepted. Format is empty/json/html; a nonempty proposal must be a valid ID and cannot combine with a nonempty cursor. A signed cursor is validated before mutation. Native forms retain the current URL, so POST allows the same query grammar and requires a nonempty query proposal to equal the command proposal. Single empty cursor remains a first-page request.

GET HTML and form-error rendering obtain CSRF tokens before a fresh same-identity session decision and transactional private reads. Session callbacks must return current authority consistently and remain bounded. Concurrent changes outside this bounded check require host lifecycle coordination; the module does not claim global atomicity across arbitrary callbacks.

For form mutations, the adapter caps and parses the body, checks duplicate/unknown/invalid-Unicode fields, and preserves parsing errors before invoking host authentication. A host CSRF lookup can therefore read cached form values without hiding a one-time ParseForm error. The host must not replace parsed input. Private form-error reload failures return unavailable before rendering content.
