# FNET-205 upstream research and adaptation handoff

Date: 2026-11-16. Phase: research only. **Integration HOLD remains in effect.** No dependency, application code, route, migration, or production configuration is added by this report. A fresh implementation agent should work only inside `future/analytics/`.

## Decision

Adopt **Chart.js 4.6.1 as an optional, locally bundled chart renderer**. Reuse its maintained bar/line rendering implementation rather than writing a chart engine. Keep Circula's accounting aggregation, authorization, privacy policy, period selection, exports, and accessible tables in native Go. No researched library provides Circula's reversal-aware accounting or safe aggregate disclosure policy; copying those from an unrelated application would not satisfy the feature.

Use a narrow adapter around Chart.js, not its repository/application scaffolding. All exact monetary data remains checked `int64` minor units on the server. JavaScript is optional. Do not make the core feature depend on a chart, network CDN, analytics provider, or another future module.

## Existing Circula seams and prototype gaps

Inspected at core baseline `2eacf7718f5bb3da3be5a288024af879076a9597`:

- `internal/domain/types.go`: `Transaction.Kind` distinguishes `trade`, `reversal`, `adjustment`, `grant`; original references, completed timestamp, ledger sequence and reversal total exist. Immutable `Entry` has signed amount and posting time.
- `internal/store/iface.go`: `Store.View` explicitly provides a consistent read snapshot; `LedgerSeq`, accounts, listings and per-transaction entries are available. Future adapter should fetch all required facts and authorization inside one snapshot rather than mix independent calls.
- `internal/service/export.go`: current export uses a snapshot manifest with network, decimal scale, ledger sequence and generation timestamp. Export download authorization is rechecked. CSV formula neutralization already exists; use the service policy patterns, not a parallel unrestricted export route.
- `internal/histbal/histbal.go`: the documented historical reader is adapter-facing and explicitly still pending a timestamp-based service read. Do not claim it supplies an implemented own-trend backend. It requires one timestamp-constrained read snapshot, not an arbitrary ledger-sequence substitute.
- `future/analytics/aggregate.go`: current prototype counts only `Completed` rows and arbitrary half-open intervals. **Filtering current transaction status to completed loses an original trade that has since been fully reversed.** Compute historical gross trade volume from immutable posting events; account for reversal events separately at their actual posting time. Current prototype lacks stock distribution, own-member trends, dormant offers, authorization, fixed-period enforcement, and rendering/export.

## Full-spec implementation plan for the next agent

1. **Versioned read model and bounded snapshot provider.** Define standalone immutable input types for network scale, snapshot revision/as-of time, accounts/member classification, paired posting facts and listing activity. A narrow `SnapshotReader`/authorization adapter must be injected. A fake provider supports isolated tests; a real Circula adapter remains unregistered on this hold branch. Reject cross-network facts, duplicate IDs, inconsistent posting pairs, unknown kinds, invalid amounts, impossible reversal links, and overflow. No write methods or dependency on another future feature.
2. **Explicit flow accounting.** Aggregate original trade postings once, not both debit/credit lines. Include originally posted trades irrespective of later reversed/disputed status. Track gross trade volume, reversal volume and net-after-reversal volume separately with clear labels; reversals in a later period belong to that later period. Exclude grants/adjustments from trade turnover and disclose any separate adjustment metric. Count unique ordinary member traders using explicit member/account facts; do not turn system accounts into people.
3. **Stock and own-member trend.** Sum immutable signed entries up to the period cutoff under the same snapshot to calculate balance stock; categorize positive/zero/negative values with integer boundaries. Never compute stock by summing only the period's trades. Own-trend access resolves the authenticated member's account, never a requested arbitrary account ID; expose their exact data only to them through an authorized adapter. Accumulate opening balance plus each period's signed movement, including reversals/adjustments. Report whether no postings exist distinctly from a genuine zero balance.
4. **Fixed periods.** Accept approved weekly/monthly periods in one configured IANA zone, bounded number of closed periods, and explicit first-day-of-week convention (proposed Monday; record as a design decision). Build calendar boundaries using local dates then UTC conversion, not 7x24h or 30-day durations. Label timezone, start/end and snapshot revision. Prevent arbitrary overlapping slices or public fine-grained filters.
5. **Privacy.** Admin-only aggregates require fresh scoped authorization. Suppress every aggregate value, chart point, export field and count when contributor count is below at least five. Suppress small histogram bins and complementary bins/totals that would reconstruct them; threshold each metric's actual contributors, not a network-wide membership count. Fixed periods reduce differencing but do not prove anonymity: define query budget/repeated-release/adjacent-period policy and document residual risks. Do not serialize raw contributors, account IDs, member balances or hidden small-cohort values into HTML/JSON/chart attributes. Raw personal-data export remains a separate existing permission, not implied by analytics-admin access.
6. **Dormant offers.** Define a configurable, bounded inactivity cutoff and use active network-visible offers' activity timestamps. This metric is listing state at the snapshot, not credit flow. Explicitly distinguish a lack of updates from a verified absence of demand; no member scoring or sanctions.
7. **Presentation and exports.** Server-render exact numeric tables with headings, caption, units/decimal scale, period/zone, suppression explanations and stock-versus-flow descriptions. Optional locally bundled Chart.js progressively enhances already-authorized aggregate data, animation disabled/reduced-motion respected. Chart tooltips/labels must not reintroduce suppressed numbers. JS numbers cannot represent all `int64` exactly: serialize exact minor units as strings; either refuse chart enhancement outside the safe-number range or derive explicitly approximate chart coordinates while tables/export retain exact values. Never silently round monetary data. Escape HTML and neutralize CSV formula cells. CSV/JSON should export the same privacy-filtered view, not raw snapshot rows. Responses require private/no-store headers.
8. **Independent packaging.** Keep dependencies/assets/notices/test fixtures under this module. Add an explicit adapter/handler constructor but no global registration, background process or root app change. Document removal, cache revision/invalidation (if any), and no-database-migration behavior if live aggregation is sufficient. Do not add caches before bounded snapshot queries require them.

## Required verification and completion gates

- Independent oracle fixtures: original trade, full and partial reversals in same/later periods, disputed/reversed current status, adjustment/grant exclusion, system accounts, two-entry balance invariants, duplicate input and signed integer overflow/underflow.
- Snapshot consistency under concurrent posting and proper network/ledger revision labels. Injected provider errors must fail closed; no partial statistics leakage.
- Weekly/monthly boundary, leap-year/month-length, UTC/local crossing, DST gaps/folds and fixed-period validation tests.
- Administrator versus ordinary member versus suspended/removed actor; own-account resolution; wrong-network rows; stale authorization/download checks; no ledger writes.
- Cohorts of 0/4/5; small/complementary histogram bins; suppressed charts and CSV/JSON contain no raw values; repeated-query policy; period-length/count limits; oversized snapshots.
- Compare exact server table/export values to chart source; `int64` values above 2^53, XSS-shaped labels, CSV formula payloads, no CDN/telemetry/network fetches, JS-disabled operation and chart failure fallback.
- Module `go test -race ./...`, `go vet ./...`, relevant fuzzing of period/parser/render data, pinned JS dependency/advisory checks and browser tests. Inspect actual built assets and both license notices.
- Human accessibility/screen-reader review and actual Circula service adapter/API/CLI/full ledger regression remain distinct acceptance gates. Unit tests or a chart demo cannot mark the complete feature done. Core integration and rollout are still held until separately authorized one feature at a time.

## Phase handoff

Research is complete enough to begin adaptation; no upstream directly supplies the full feature. Implement the complete isolated analytics engine and accessible view, reuse Chart.js for optional visualization, and keep outstanding real-core adapter/manual qualifications explicit. Do not hide incomplete requirements by relabeling a chart or integer aggregator as FNET-205 complete.
