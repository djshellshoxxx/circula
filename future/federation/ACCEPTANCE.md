## Explicit qualification still required

A fresh independent audit has reproduced the standalone evidence and fixed the findings recorded in AUDIT.md. Synthetic HTTP redirect/slow/oversize/error policy, inbox/rate boundaries, closed-DB restore and dependency advisory scanning now pass; The new audit tests cover maximum ordinary publication/departure capacity, consent/peer/inbox/owner boundaries and incompatible-schema/view/corrupt-state rejection. Actual live-peer TLS/protocol qualification, a future versioned protocol/schema upgrade, integrated rate-limit policy and manual screen-reader/WCAG checks remain evidence gaps. These are not marked passed.

The real Circula adapter must map the existing service/store transaction rather than open a nested immediate transaction; connect withdrawal to member departure/suspension/listing deletion atomically; and test unchanged ledger hash/invariants, API compatibility and no-JS behavior in the actual application. No core file is changed here. Production key custody/distribution, external peer setup and a reviewed final protocol ADR remain release gates.

## Local contracts

- Peer ingress: an explicitly constructed `Ingress{Store, Local, Remote}` accepts only POST `application/circula-discovery+jws`, max16KiB. Route resolution supplies configured network/peer IDs; the event cannot select local authority.
- `Members` provides GET browse and POST form actions `consent`, `share`, `withdraw`; trusted HostAuth validates identity and cookie CSRF. `Admin` provides enable/disable/approve/revoke/revoke-key. Route registration is deliberately absent.
- `RunCLI`: status, browse, enable, disable, approve PEER ENDPOINT KID BASE64_PUBLIC_KEY FROM_RFC3339 UNTIL_RFC3339, revoke PEER, revoke-key PEER KID, consent PEER LISTING on|off, queue PEER LISTING REQUEST_ID publish|revoke, retry PEER REQUEST_ID, maintenance, depart MEMBER, withdraw-listing LISTING. Host supplies identity/connection/auth; no private key argument is accepted.

## Operations

Use a caller-owned SQLite connection and explicit `Migrate` before use. It adds only `discovery_*` tables/indexes. No schema is applied automatically or removed on disable. The baseline prototype has no schema, so this is the first candidate schema. Existing same-name tables/indexes must match its declaration and object type; an unknown schema fails closed inside the migration transaction. The audit adds an additive listing-order index. Backup with SQLite's consistent online backup API or a closed-DB copy including a checkpointed WAL; restore the entire DB consistently, including replay/sequence/tombstone metadata. Never restore only listing bodies or reset sequence tables. Protect DB/backups as user data.

Run explicit bounded Pending/Dispatch batches. Do not log wire bodies/private signing material. Monitor redacted state, attempts, quotas and last successful delivery. Revoke a compromised public key locally before admitting a replacement with a fresh ID; configure replacement trust bilaterally outside events. Revocation does not imply reapproval or deletion of high-water marks.

Call Maintenance to remove expired bodies; replay hashes, tombstones, sequences and request IDs remain to prevent replay. Lifetime quotas deliberately stop new work rather than destroy safety records. A future peer epoch/reset and metadata compaction require independent protocol review; there is no unsafe automatic reset command. Disable stops ingress/egress and cancels queued deliveries while leaving core trades untouched. Remotes may keep previously shared content until expiry; a partition cannot guarantee immediate remote deletion. Re-enable only after explicit review.
