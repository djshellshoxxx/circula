# Experimental discovery protocol candidate — v2

Status: candidate for isolated tests and fresh security review, not production-approved. Integration HOLD.

Use standard JWS Compact EdDSA with pinned go-jose v4.1.9. Protected header contains exactly `alg=EdDSA`, `typ=circula-discovery-v2+jws`, and locally trusted `kid`. JSON payload is exactly Go's declared struct encoding, version 2, without unknown/duplicate/alternate encodings. Prototype v1 helpers remain legacy standalone tests; the v2 inbox accepts only compact JWS and never falls back.

Each configured bilateral peer binds local and remote network IDs, fixed HTTPS endpoint, publish scope, and locally administered Ed25519 public keys with validity windows. Events cannot introduce or rotate trust keys. Local admin rotation adds a fresh key ID; revocation immediately disables acceptance under that key. No private key is stored by the module. Signing keys are explicitly supplied by a host key provider for dispatch; their storage/distribution remain production qualification.

Lifetime is at most 24 hours, clock skew at most five minutes. Monotonic per-listing revisions and durable content/tombstone high-water marks prevent resurrection. Same event ID/hash is idempotent; ID/hash conflicts and equal revision/content conflicts reject. High-water marks, replay IDs and tombstones are retained indefinitely in this candidate; a later bounded-retention design cannot delete them without a separately reviewed peer epoch/reset. Bounded peer/event/listing/outbox quotas fail closed instead of evicting safety records.

Only title, description, category and consented coarse-area labels are shared. Owner identity remains an internal local consent record, never published. No links are dereferenced. No balance, proposal, settlement or remote administration kind exists. Network and peer default disabled. Sharing is scoped to one peer and is not onward-relay authorization.

The SQL reference adapter supplies one immediate transaction to fresh authentication/source callbacks. Final core adapter must use the existing Circula transaction boundary, without opening a nested write transaction. HTTP delivery is at-least-once; inbox acceptance is transactionally idempotent. Partition retry is bounded and never blocks core trades, since this module is not imported by core.
